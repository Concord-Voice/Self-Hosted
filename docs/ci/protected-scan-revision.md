# Protected PR scan revision

The required PR verifier compares each selected Code Scanning analysis to the protected selector's exact `merge_sha`. GitHub can produce two merge commit objects with the same base, head, and tree but different timestamps. The event checkout SHA and the PR API's current `merge_commit_sha` can therefore differ. A matching tree is not enough to establish that the selected revision was scanned.

For protected `external-verdict` calls, `pr-ci.yml` forwards the selector's known flag, PR number, head, base, and merge SHAs to Semgrep, ESLint, and govulncheck. Each callee validates the required-main caller and base-repository provenance, then re-reads the public PR and selected merge commit before checkout. The live PR's head repository must exactly match the canonical event head repository; its head, base, and merge SHAs must still match the selection. The merge commit must have exactly those base and head parents. An invalid or unavailable tuple stops the job before repository checkout and dependency installation. The three scanners then check out the selected merge SHA, assert actual `HEAD`, and request all four SARIF uploads against that SHA and `refs/pull/<number>/merge`. The protected verifier still performs its later current-PR and upload-evidence checks; no tree-equivalence or stale-upload exception is added.

Protected fork PRs still execute the scanners through the same selected-revision check. The upstream SARIF upload action ignores explicit ref and SHA overrides for fork PRs. Its fork uploads can therefore retain event attribution; if the event and selected merge objects differ, the unchanged protected verifier can still reject that fork run. This change makes no new fork upload-attribution guarantee.

Only the protected call uses this preflight. Ordinary PR and main/nightly scanner calls retain their event checkout and upload identities. The protected path requires no new token grant: it checks `GITHUB_REPOSITORY` equals this public repository before two read-only GitHub REST GETs, [Get a pull request](https://docs.github.com/en/rest/pulls/pulls#get-a-pull-request) and [Get a commit](https://docs.github.com/en/rest/commits/commits#get-a-commit). GitHub documents both endpoints as available for public resources without authentication or fine-grained token permissions; the existing `contents: read` token and scanner permissions remain unchanged. No PR-supplied source executes before the preflight.

This source change alone does not update the immutable `pr-ci` pin in the protected required workflow. That pin and its verifier expectations need separate reviewed delivery before live required runs use the new producer. Do not retry a blocked run as proof of this undelivered change.
